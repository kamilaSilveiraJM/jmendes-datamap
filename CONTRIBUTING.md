# Contribuição

## Fluxo obrigatório
Issue → Branch → Commit → Pull Request → Validação → Aprovação → **Merge**

1. Toda funcionalidade/correção tem **Issue** vinculada.
2. Branch a partir da `main`: `feat/<n>-descricao`, `fix/<n>-descricao`, `docs/<n>-descricao`.
3. Commits curtos e referenciando a Issue (`#n`).
4. **Pull Request obrigatório** (template), com Issue vinculada (`Closes #n`) e code review.
5. **Nenhum merge sem autorização explícita da responsável pelo produto (Kamila Silveira).** Isso vale para qualquer PR, inclusive de documentação.

## Dúvidas
Informação ausente ou inconsistente nunca é inventada: abra Issue com o rótulo `a-validar`.

## Segurança e privacidade
Sem segredos no repositório. Sem dados pessoais ou conteúdo operacional no catálogo, em exemplos ou em testes.
